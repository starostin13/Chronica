# Реализация фильтра по размеру файла

## Описание проблемы

Иногда Telegram отклоняет отправку файлов с сообщением "Изображение слишком большое". Необходимо было реализовать механизм запоминания максимального размера файла и фильтрации файлов при выборе.

## Реализованное решение

### 1. Структура кеша (yaHelper.py)

Добавлены новые поля в глобальный кеш и файловый кеш:
```python
_folder_scan_cache = {
    "all_files": [],
    "scan_time": 0,
    "cache_expires": 0,
    "folders_scanned": 0,
    "max_file_size": None,
    "file_sizes": {},
}
```

Также создается файл `folder_scan_cache.json` в `credentials.temp_folder`.
В нем сохраняются:
- `max_file_size`
- `file_sizes` — известные размеры файлов по их пути на Яндекс.Диске

### 2. Новые функции в yaHelper.py

#### `set_max_file_size(file_size_bytes)`
- Сохраняет размер файла, который не удалось отправить
- Обновляет максимум только если новый размер меньше текущего
- Вызывается из bot.py когда Telegram отклоняет файл

#### `get_max_file_size()`
- Возвращает текущий максимальный размер файла
- Возвращает `None` если ограничения нет

#### `get_known_file_size(file_obj)`
- Сначала берет размер из `file_obj.size`
- Если `size` отсутствует, пытается найти размер в файловом кеше

#### `downloadFile(...)`
- После успешного скачивания сохраняет реальный размер файла в файловый кеш
- Это используется как запасной вариант, если API Яндекс.Диска не отдал `size`

### 3. Фильтрация в find_available_photos()

Добавлена фильтрация файлов по размеру перед возвратом результата:
```python
max_size = _folder_scan_cache["max_file_size"]
if max_size is not None:
    all_files = [
        f
        for f in all_files
        if get_known_file_size(f) is None or get_known_file_size(f) <= max_size
    ]
```

Файлы с неизвестным размером не исключаются автоматически.

### 4. Интеграция с bot.py

Обновлены функции отправки для сохранения размера при ошибке:
- `try_send_small_image()` - строка 354-355
- `try_send_video()` - строка 395-396

При ошибке отправки:
```python
known_file_size = get_known_file_size(photo)
if known_file_size:
    set_max_file_size(known_file_size)
```

### 5. Обновление clear_photo_cache()

Функция теперь также сбрасывает:
- `max_file_size`
- `file_sizes`

и сохраняет очищенное состояние в файловый кеш.

## Источник данных о размере

Размер файла берется в таком порядке:
1. Из API Яндекс.Диска через атрибут `photo.size`
2. Из файлового кеша `folder_scan_cache.json`
3. После скачивания — через `os.path.getsize(...)`, если размер не пришел из API

## Логирование

Добавлены информативные сообщения в консоль:
- При установке максимума: `📏 Установлен максимальный размер файла: X.XX MB`
- При фильтрации: `📏 Отфильтровано N файлов превышающих максимальный размер X.XX MB`

## Поведение системы

1. **При старте**: максимальный размер не установлен (`None`), все файлы доступны
2. **При ошибке отправки**: известный размер файла сохраняется как максимум
3. **При выборе файлов**: автоматически исключаются только файлы с известным размером больше максимума
4. **При скачивании**: размер файла попадает в файловый кеш и может использоваться позже
5. **При перезапуске**: максимальный размер и кеш размеров восстанавливаются из файла
6. **При очистке кеша**: максимальный размер и кеш размеров сбрасываются
