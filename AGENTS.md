# Инструкции для AI-агентов

Этот документ содержит правила и рекомендации для AI-ассистентов по работе с кодом проекта Chronica.

## 1. О проекте

**Chronica** — это Telegram-бот на Python, который каждый день отправляет в чат случайную фотографию из архива на Яндекс.Диске.

- **Основная логика:** `bot.py`
- **Работа с API Яндекс.Диска:** `yaHelper.py`
- **Конфигурация:** `credentials.py`

## 2. Технологический стек

- **Язык:** Python 3.11+
- **Ключевые библиотеки:**
  - `pyTelegramBotAPI` (telebot) — для взаимодействия с Telegram.
  - `yadisk` — для работы с Яндекс.Диском.
  - `Pillow` (PIL) — для обработки изображений.
  - `pillow-heif` — для поддержки формата HEIC.

## 3. Стиль кода и форматирование

- **Форматирование:** Весь код на Python должен быть отформатирован с помощью `black`.
- **Проверка стиля:** Используйте `flake8` для проверки кода на соответствие PEP 8.
- **Длина строки:** Максимум 79 символов.
- **Переносы строк:** При многострочных вызовах функций или методов каждый аргумент должен располагаться на новой строке с отступом.
- **Пустые строки:** Не должны содержать пробелов или других символов.
- **Комментарии и документация:** Пишите комментарии и docstrings на русском языке. Они должны быть ясными и по делу.
- **Именование:** Используйте `snake_case` для переменных и функций (например, `find_available_photos`).
- **Размер файла:** Старайтесь, чтобы файлы не превышали 400-600 строк. Длинные файлы следует рефакторить, разбивая на более мелкие и сфокусированные модули.

## 4. Правила разработки

- **Обработка ошибок:** Все операции, которые могут вызвать сбой (сетевые запросы, работа с файлами), должны быть обернуты в блоки `try...except`.
- **Сообщения для пользователя:** Ошибки, которые видит пользователь в Telegram, должны быть краткими, понятными и на русском языке. Не показывайте пользователю технические детали или трейсбеки.
- **Логирование:** Используйте `print()` для вывода информации о ходе выполнения в консоль. Сообщения должны быть информативными (например, какой файл обрабатывается, результат операции).
- **Зависимости:** Все новые библиотеки должны быть добавлены в файл `requirements.txt`.
- **Пути к файлам:** Для работы с путями используйте `os.path.join()` для обеспечения кросс-платформенной совместимости. Не используйте жестко закодированные слеши (`/` или `\`).

## 5. Основной функционал бота (КРИТИЧЕСКИ ВАЖНО)

**Эти требования НЕ ДОЛЖНЫ изменяться при любых рефакторингах и переписываниях кода:**

### 5.1 Автоматическая отправка изображений по расписанию

- **При старте приложения:** Должна создаваться задача, которая запустится через случайное количество часов.
- **После выполнения задачи:** Должна автоматически ставиться в очередь следующая задача с новым случайным интервалом.
- **Логика выбора изображений для расписания:** Сначала нужно найти изображения, сделанные в тот же день и месяц, но в любой год (например, если сегодня 27 сентября, искать все фото сделанные 27 сентября любого года). Только после этого выбрать случайное изображение из найденных.
- **Отправка в несколько чатов:** При отправке по расписанию изображение отправляется в каждый чат из `chat_ids` разное. Алгоритм: сначала собрать все подходящие по дате изображения, затем случайным образом выбрать уникальное изображение для каждого чата.

### 5.2 Обработка команды /start

- **Проверка чата:** Команда `/start` обрабатывается ТОЛЬКО от чатов с ID, перечисленными в `chat_ids` из конфигурации.
- **Отправка в конкретный чат:** Изображение отправляется ТОЛЬКО в тот чат, откуда была получена команда `/start` (не во все чаты).
- **Быстрый ответ:** При получении `/start` должно отправляться просто случайное изображение из всего архива (без фильтрации по дате) для ускорения процесса ответа.

### 5.3 Конфигурация чатов

- Список разрешенных чатов должен храниться в переменной `chat_ids` в файле конфигурации.
- Все функции отправки должны проверять права доступа перед отправкой сообщений.

## 6. Пример рабочего процесса

1.  **Прочитать задачу:** Внимательно изучи запрос пользователя.
2.  **Внести изменения:** Аккуратно измени код в соответствии с правилами выше.
3.  **Отформатировать код:** Перед завершением работы выполни форматирование измененных файлов с помощью `black`.
4.  **Проверить синтаксис:** Убедись, что в коде нет синтаксических ошибок.
5.  **Протестировать:** Если были внесены значительные изменения, запусти бота и проверь его работоспособность.
